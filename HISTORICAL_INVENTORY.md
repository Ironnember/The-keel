## Recovered capability map

### Keep in Keel 1.0 trajectory

- normalized provider/executor adapters;
- deterministic request parsing and schema validation;
- exact execution-object validation against Pulpo permit data;
- payload-size/resource ceilings;
- process supervision and graceful shutdown/drainage;
- health/readiness gates;
- bounded circuit breaking and failover only where changing provider does not change the authorized consequence;
- execution credential custody isolated from intelligence;
- execution attempt receipts;
- crash/restart state needed to avoid duplicate consequential transmission;
- unknown-outcome handling without blind retry;
- optional suspension/resume for long-lived operations after exact state semantics are proved;
- telemetry sufficient for Pulpo reconciliation and cost evidence.

### Keep out of Keel authority

- semantic intent approval;
- human/machine authority decisions;
- policy expansion;
- budget authorization or self-increasing quotas;
- model/retrieval-derived permission;
- canonical audit truth;
- governed learning/memory authority;
- automatic broadening of scope during failover;
- 'safe payload' implying 'authorized consequence'.

### Defer from V0

- LLM routing/gateway product breadth;
- RAG/pgvector/HNSW caching;
- generalized multi-agent orchestration;
- billion/trillion-agent scale mechanisms;
- enterprise multi-tenancy product surface;
- outcome pricing / GTM;
- model-specific reasoning engines;
- broad skill marketplace integration.

## Highest-value recovered lessons

1. **Execution suspension is valuable only if authority is revalidated on resume.** Historical Sailbox/Salebox concepts survive, but a resumed operation must not inherit stale execution authority.
2. **Failover cannot mutate consequence.** A provider failover is allowed only if the exact authorized action semantics remain invariant; otherwise Pulpo must issue a new permit.
3. **Budget reservation belongs across the seam.** Pulpo authorizes the maximum spend/resource envelope; Keel may atomically reserve/consume/refund within that envelope but cannot enlarge it.
4. **Tool scanning is evidence, not permission.** Signed/scanned code may satisfy execution-integrity requirements, but cannot create authority.
5. **Execution receipts are not consequence truth.** Historical out-of-band logging becomes evidence input to Pulpo reconciliation, not a second ledger.
6. **Unknown outcome must survive restart.** Keel must preserve 'attempted/unknown' states so restart cannot silently retry consequential operations.
7. **Local/sovereign execution fits Keel naturally.** The old VPC/bare-metal direction remains compatible with the current separation because custody and execution can stay near the resource while Pulpo remains the independent authority plane.
